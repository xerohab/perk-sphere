# Member quote/preparation gateway — unpublished disabled preparation

`giftMemberCheckout` accepts either `action:'quote'` with an offer, original UUID and recipient fields, or `action:'prepare'` with the original quote digest. It derives member ownership from the actual SDK auth.me() request, requires an explicit Bearer credential and `PERKSPHERE_GIFT_CHECKOUT_MEMBER_ENABLED=true`, rejects blocked/unsupported accounts and rechecks SDK identity/status around dispatch and output. Browser ownership, price, currency, credential and plan injection are refused. Input and output are bounded and validated; no payment, capture, dispatch or live readiness is claimed.

The existing Linux client signs only the fixed `/v1/perk-sphere/gifts/quotes` and `/v1/perk-sphere/gifts/checkouts/prepare` requests. Canonical member actor data is added server-side. The matching Linux bridge verifies HMAC and nonce, then asks the fixed `trustedGiftCheckoutMemberAuthority` callback for current account permission tied to action, canonical command digest, nonce and deadline. Callback scope excludes recipient values. Digests are not anonymization.

The trusted callback verifies the existing inbound HMAC before service-role account lookup. It checks current account role/status and the member gate; it does not verify buyer market, age, recipient semantics or funding. Its nonce is a signed request identity, not an SDK session token. The member gateway's separate SDK checks are the login-session boundary. The Linux quote/checkout policy adapters still require independently verified buyer/recipient evidence and approved terms.

These two functions and their contract are source preparation only; this commit does not publish them, enable their gate or mount Linux routes. No checkout UI is offered and no provider transaction is created. Exact quote/preparation request identities must be retained across uncertainty; an unavailable response is not proof that no database record was committed. Production composition, genuine member/provider acceptance and independent backup/restore remain outstanding.
