# Member voucher reveal component and gateway

This checkpoint prepares GiftVoucherReveal and revealGiftVoucher. The member component is not mounted in a member route or wallet section, and the gateway remains disabled unless PERKSPHERE_GIFT_VOUCHER_MEMBER_ENABLED is explicitly true. Production delivery is not enabled.

The gateway uses createClientFromRequest and the actual current SDK auth.me() owner. It rejects blocked accounts, ambient-cookie-only requests, query strings, non-JSON/encoded transport, more than 4 KiB of input, caller-selected ownership fields and invalid UUIDs. It signs only the exact intent/request pair plus its server-resolved member actor to /v1/perk-sphere/gift-vouchers/reveal. Current authenticated owner and gate are checked again before plaintext can leave the function. No admin role or generic admin bypass authorizes another member's voucher.

giftVoucherContract strictly validates the matching intent, canonical plaintext receipt, bounded fields, HTTPS redemption URL without credentials/custom ports, exact currency/minor-unit value shape and false provider-delivery claim. Unexpected private fields are rejected. This browser-side contract does not replace the Linux quote-bound hostname policy.

GiftVoucherReveal requires an explicit click before requesting data. It uses the exact original in-memory UUID for a failed-response retry and does not persist request or receipt in browser storage. It renders instructions and code as React text nodes, uses exact integer minor-unit formatting, and opens redemption URLs with noopener/noreferrer and no-referrer. It clears the displayed reveal on blur, hidden-document events, account/role/status or intent changes, explicit Hide, unmount, one minute or earlier expiry. Late responses and retained callbacks cannot retarget another account or voucher. Clearing component state is not a promise of cryptographic erasure of JavaScript strings or browser screenshots.

Validation on 11 November 2026 passed all 508 web tests plus lint and build. Tests cover SDK member ownership, inactive/unauthenticated/cookie-only denial, body limits, caller identity injection, post-read account changes, plaintext-safe error handling, explicit reveal/text rendering, blur clearing, original request retry, duplicate submissions, account/intent changes and blocked accounts. Credentials, sessions and vouchers in tests are synthetic.

Before mounting/enabling: implement the signed Linux owner-authority bridge with current ownership rechecks, prepare operational encryption keys and tested restore procedures, complete genuine receipt ingestion and funded purchase/delivery flows, and perform authorized member/session/provider acceptance. Do not activate the member gateway merely because its component builds. No real voucher, financial balance, production key or provider operation was created by this checkpoint.
